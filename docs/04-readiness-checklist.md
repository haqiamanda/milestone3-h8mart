## 2. Kesiapan Sistem Existing

| Sistem | Cara terhubung | Rate limit / SLA yang diketahui | Perilaku bila down | Siapa dihubungi |
| --- | --- | --- | --- | --- |
| Merchant Stock API | HTTP Request WF1 `Ambil Stok Merchant API` ke service `mock-api`, sinkron 12 merchant per batch; upsert ke `core.merchant_stock` | Rate limit dan SLA **tidak dinyatakan sebagai jaminan produksi** oleh mock; jadwal rancangan setiap 15 menit | Retry pada permintaan; kegagalan permanen satu merchant (contoh M009, HTTP 500) dicatat di `ops.dead_letter`, merchant lain tetap dilanjutkan; heartbeat `down` ketika target tidak tercapai | Tim Ops H8Mart / administrator mock API (simulasi) |
| Payment API | HTTP Request WF4 untuk voucher/refund; gunakan `Idempotency-Key` dan pencatatan state di PostgreSQL | Batas laju/SLA provider nyata **tidak tersedia** (mock) | Respons gagal/503 tidak boleh dianggap pembayaran berhasil; catat gagal/dead-letter, kirim alert dan lakukan rekonsiliasi manual sebelum retry ulang | Finance/Ops H8Mart / administrator mock Payment API |
| Notification (mock API) | HTTP Request dari WF1, WF4 dan WF5 ke `mock-api` | Rate limit dan SLA tidak diketahui; mock, bukan layanan pengiriman terjamin | Gagal notifikasi tidak boleh mengubah hasil transaksi menjadi sukses palsu; rujuk execution dan alert Telegram, lakukan retry terkontrol jika dibutuhkan | Ops H8Mart / administrator mock API |
| Telegram Bot API (digest, alert, approval, chat) | Credential Telegram n8n: digest WF1, approval manusia WF4, alert WF5; **chat merchant belum diimplementasikan via Telegram** | Rate limit mengikuti kebijakan Telegram; angka spesifik belum diuji, tidak ada SLA kontraktual di proyek | Eksekusi mencatat error; pantau WF5/Executions. Jika Telegram tidak tersedia, approval refund besar tetap menunggu atau ditangani Ops secara manual—**jangan auto-approve** | Operator bot Telegram / Ops |
| PostgreSQL | Service `postgres` di jaringan Docker; skema `core.*` dan `ops.*`; `mcp_reader` baca-saja, `ops_writer` untuk perubahan Ops | Satu instance dalam satu VM; tidak ada jaminan HA/SLA internal | Kegagalan koneksi menyebabkan node SQL gagal dan perlu alert; jangan menyatakan order/refund tersimpan jika commit DB tidak sukses. Backup-restore belum diverifikasi | Administrator database/EC2 |
| LLM provider | OpenAI Chat Model dari WF3, diakses melalui n8n Credentials dan MCP Client WF2 untuk data merchant | Rate limit, uptime, dan biaya mengikuti akun/provider; kuota aktual **belum diverifikasi** | Guardrail structured output dan fallback menuju tiket `ops.tickets`/CS ketika model atau parser gagal atau confidence di bawah 0,8; tidak memberi jawaban tak berdasar | Administrator OpenAI / Customer Service H8Mart |

**Catatan kesiapan integrasi:** Data H8Mart adalah sintetis dan mock API. Belum ada kontrak SLA nyata, prosedur eskalasi vendor, atau pengujian beban terukur. Pada WF3, `merchant_id` berasal dari payload webhook; **Header Auth saja tidak mengikat pengguna ke merchant tertentu**, sehingga isolasi tenant belum memadai untuk data merchant nyata.

## 4. Risiko Residual dan Keputusan Kesiapan

| Risiko | Dampak | Mitigasi / aksi sebelum production riil |
| --- | --- | --- |
| Isolasi merchant WF3 belum berbasis identitas | Merchant bisa meminta data merchant lain melalui payload bila hanya token bersama yang digunakan | Gunakan autentikasi per merchant, mapping identitas server-side, filter SQL wajib berdasarkan identitas terverifikasi, test negatif lintas merchant |
| Satu EC2 menampung semua service | Single point of failure; pemulihan bergantung pada backup | Snapshot/backup terjadwal terenkripsi, uji restore, observabilitas host, batasan resource |
| Schedule WF1 sengaja dimatikan sesudah evidence | Tidak ada sinkron berkala, digest terjadwal, dan heartbeat rutin selama tidak aktif | Status ini **sesuai instruksi submission**, bukan kesiapan operasi 24/7; jangan nyatakan monitoring normal saat schedule nonaktif |
| Export publik belum memenuhi aturan placeholder/nama credential mentor secara persis | Pengurangan skor governance atau kesulitan import bagi penilai | Ubah placeholder push ke `ISI_TOKEN_PUSH_KUMA`; pertahankan nama/type credential yang aman tanpa ID/secret jika diminta, jelaskan mapping di `docs/05-readme-solusi.md` |
| Pengendalian secret dan port belum diaudit tuntas | Potensi paparan token, endpoint atau data | Scan repo **termasuk gambar**, tinjau Caddyfile dan Security Group, gunakan credential placeholder, rotasi credential yang pernah terekspos |
| Gangguan Payment API setelah request terkirim | Risiko status transaksi ambigu / double refund | `Idempotency-Key`, query state sebelum retry, rekonsiliasi Finance, approval manusia untuk refund besar |

**Keputusan readiness (per 15 November 2026):** **Siap untuk demo/penilaian terkontrol dengan syarat**, karena alur utama sudah dibangun dan diuji. **Belum siap untuk melayani merchant/pelanggan nyata di produksi penuh**, terutama karena kontrol secret/akses belum diaudit tuntas, isolasi tenant masih lemah, backup-restore dan monitoring/billing belum tervalidasi. Daftar *Belum* di atas menjadi *action list* dan tidak boleh diubah menjadi *Siap* tanpa bukti.
